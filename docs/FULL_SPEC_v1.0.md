# AI 社群內容自動化系統完整需求規格書 v1.0

日期：2026-09-24

## 1. 專案目標
建立可長期運作的 AI 社群內容生產系統，整合選題、內容生成、素材搜尋、風險檢查、排程、發布、成效回收與 AI 優化。

核心原則：
- 品質優先，不硬湊數量
- 每週目標 450～550 則
- 一般內容盡量自動化
- 價格、日期、簽證、重大新聞、政治、戰爭、災害、安全事件等需人工審核
- 同主題可跨平台，但最終文案、封面、字幕、CTA、發布時間應差異化

## 2. KPI
- 週內容量：450～550 則
- 內容差異化：越多越好
- 商業導流：整體約 20%
- 官方 Facebook 商業導流約 40%
- 區域 Facebook 商業導流約 10%
- 平台資源優先順序：Instagram > YouTube > Threads > TikTok

## 3. 內容來源
- 公司官網行程、產品、活動與旅遊資訊
- 講座與活動
- AI 延伸旅遊知識
- 旅遊新聞、熱門話題、節慶
- 舊文章與歷史貼文
- QNAP NAS 照片與影片
- 合法可商用外部圖庫 API

新聞必須附來源並摘要／重寫；一般新聞需多來源比對；重大事故、政治、戰爭、災害與安全事件需人工審核。

## 4. Facebook
Facebook 共 10 個帳號，其中 9 個納入系統：

1. 航向世界旅遊：官方總帳號，全區域，商業約 40%，每日上限 5 則
2. 航向世界旅遊-台中：不納入自動化
3. 航向世界 非洲冒險趣：非洲，商業約 10%
4. 航向世界 俄羅斯冒險趣：俄羅斯，商業約 10%
5. 航向世界 大洋洲冒險趣：大洋洲，商業約 10%
6. 航向世界 中亞/中東冒險趣：中亞／中東，商業約 10%
7. 航向世界 歐洲冒險趣：歐洲，商業約 10%
8. 航向世界 東南亞/南亞冒險趣：東南亞／南亞，商業約 10%
9. 航向世界 拉丁美洲冒險趣：拉丁美洲，商業約 10%
10. 航向世界 北美洲冒險趣：北美洲，商業約 10%

區域帳號每日上限 3 則。週末照常發文，增加靈感、故事、互動、景點照片與旅遊知識。相同主題可同日出現在不同帳號，但文案需不同；圖片盡量不同，無合適素材時可共用。

## 5. Instagram
- 高質感視覺優先，避免 AI 感與過度模板化
- 單圖、Carousel、Reels 混合
- Carousel 最多 10 張
- 封面標題要短，不做傳統 EDM
- 文案長短依內容，但前 1～2 行需有吸引力
- Hashtag：固定品牌標籤 + AI 主題標籤，總量約 5～8 個
- 初期人工建立 8～12 套模板
- AI 可提出新模板，但必須人工核准
- 各地區有主色與部分專屬模板

## 6. YouTube
- 頻道 A：官方品牌／行程／深度內容
- 頻道 B：旅遊知識／Shorts／流量內容
- Shorts 比例較高，可抓 70～80%
- Shorts 每日上限 2 支
- 長影片不固定產量，有好內容才上
- 新剪輯／AI 重組與高風險長片必須人工審核
- 第一頻道長影片可自動拆成多支 Shorts；AI 可自動選精華、轉直式、加字幕、標題與排程；高風險內容仍需人工確認

## 7. Threads
- 旅遊知識、短觀點、互動問答、熱門話題、旅遊新聞
- 以高互動短內容為主
- 每日動態發布，上限 5 則

## 8. TikTok
- 帳號 A：旅遊靈感／景點視覺
- 帳號 B：旅遊知識／攻略／互動
- 先好看、節奏快，再談資訊與導流
- 每日動態發布，上限 2 支

## 9. 跨平台規則
- 同主題可跨平台，但最終文案需差異化
- 同素材可用於 IG Reels、YouTube Shorts、TikTok
- 發布時間錯開
- 封面、標題、文案、字幕樣式、CTA 盡量不同
- 系統依內容類型、過去成效與平台優先級決定先發平台

## 10. AI Content Engine
- 多來源自動建立選題池
- 建立母稿與平台／帳號版本
- 自動產生標題、短文、長文、Hashtag、CTA、圖片搜尋詞、短影音腳本
- 依平台與帳號規則調整
- 依平日／週末、熱門話題與成效調整內容組合
- 高成效內容可延伸主題
- AI 可調整內容比例，但每類須有上限，避免單一主題壟斷

## 11. 查重
- 同主題週次數限制
- 同帳號同主題冷卻時間
- 文案語意查重
- 同景點／標題角度／照片使用情況可納入參考
- 圖片可重複使用，但需保留使用紀錄

## 12. 圖片
- 優先公司素材 + 免費商用圖庫 API
- 不以 AI 生圖作為主要旅遊照片來源
- AI 可自動搜尋、選圖、配文、排程
- 記錄來源、攝影師、授權／下載資訊與回鏈
- 偵測人物、品牌 Logo、敏感場景，有風險時停止自動發布

## 13. QNAP NAS
- 只讀索引，不修改原始檔
- 可掃描全部照片／影片
- 建立縮圖、AI 標籤、衍生資料
- 不重新命名、不搬動、不覆寫
- 照片標籤：國家、城市、景點、季節、天氣、白天／夜晚、有人／沒有人、交通工具、建築、自然景觀、食物等
- 不做人臉身分辨識
- 支援自然語言搜尋
- 顯示縮圖、檔名、原始路徑、AI 標籤、拍攝地點、拍攝日期、使用次數與最近使用貼文

## 14. NAS 影片
- 自動影片摘要、關鍵字與場景
- 可用片段時間點索引
- 支援自然語言搜尋片段
- 自動裁切
- 自動字幕
- 自動轉直式
- 短影音優先使用公司既有素材
- 若不足，先搜公司其他區域／舊資料夾，再考慮外部圖庫

## 15. 短影音
- 品牌字幕樣式
- 關鍵字可放大／強調
- 各平台不同字幕版型
- Logo、片尾 CTA、地點、國旗、景點標籤
- 背景音樂與簡單轉場
- 音樂來源：公司授權 + 可商用免版稅
- AI 自動選音樂
- 新模板首次使用需人工預覽
- 高風險內容需人工預覽
- 一般內容可自動發布
- 每天提供已排程影片清單與預覽
- 不滿意時只需整支停掉；系統可重生或換主題補位

## 16. 風險
- 綠燈：一般景點、文化、旅遊靈感、低風險知識 → 自動排程
- 黃燈：價格、日期、促銷、講座、產品資訊 → 人工審核
- 紅燈：簽證／法規、重大事故、政治、戰爭、災害、安全事件 → 必須人工審核

## 17. Dashboard
- 每日內容清單
- 顯示標題、平台、帳號、時間、縮圖、文案摘要、來源、風險、審核狀態
- 可修改、停用、改時間
- 可插入公司指定重要內容
- 可停主題、帳號或單篇內容
- 一鍵暫停全部自動發布
- 圖文被停掉後依當天總量決定是否補位，不硬湊
- 影片被停掉後可重生或換主題

## 18. 排程與發布
- 依歷史成效優化時段
- 設每日上限與最短間隔
- 每篇有 idempotency key
- 失敗自動重試，但有最大次數
- Token 到期檢查、更新與告警
- 所有結果寫入 publish_log
- 當天實際量下降時不硬補

## 19. 成效學習
- 回收觸及、曝光、互動、留言、分享、點擊、轉換
- 分析主題、帳號、時段、格式、素材
- 高成效內容可延伸
- AI 可調整下一週比例，但受上限規則約束
- Facebook 占比不固定，依成效調整

## 20. 資料模型
- source_items
- topics
- posts
- social_accounts
- assets
- schedule
- publish_log
- metrics
- content_fingerprint
- media_index
- media_usage
- review_queue

## 21. 系統架構
資料來源 / 官網 / 講座 / 新聞 / NAS / 圖庫
→ AI Content Engine
→ Quality & Risk Engine
→ Media Search / NAS Index / Stock API
→ Daily Content Planner
→ Review Queue
→ Social Publisher（Postiz 優先）
→ Facebook / Instagram / Threads / TikTok / YouTube
→ Analytics / Metrics
→ AI Optimization

## 22. 部署
- Phase 1：Windows 本機 POC
- Phase 2：評估 QNAP NAS／內部伺服器
- 正式：24 小時主機，NAS／內部伺服器或 VPS
- 正式環境不得依賴個人電腦
- 需 Docker / Docker Compose、固定網域、HTTPS、DB 備份、Log、Monitoring、自動重啟、Secret 管理

## 23. 安全
- Token、OAuth Secret、密碼不可提交 GitHub
- Secret 使用環境變數或 Secret Manager
- Facebook 個人 Profile 不使用非官方瀏覽器機器人
- 帳號需區分 official / unofficial / auto_publish_allowed
- Dashboard 至少有管理者、審核者、唯讀角色
- 人工審核、停用、排程修改保留 Audit Log

## 24. 開發流程
- Repository：sammyzomb/AI-Social-Content-Automation
- main：穩定分支
- 新功能走 feature branch / PR
- Phase 1 POC：phase1-poc
- GitHub Actions 自動測試
- Postiz 第一候選；BrightBean Studio 第二候選

## 25. Roadmap
### Phase 1 POC
驗證 AI → 檢查 → 排程 → 發布 → Log 閉環。

### Phase 2 MVP
100～200 則／週；內容池、Dashboard、審核、圖片 API、1～3 平台。

### Phase 3 Scale
300 則／週；NAS 索引、影片分析、更多帳號、Retry / Token。

### Phase 4 Target
450～550 則／週；全平台、AI 優化、成效回饋、短影音自動化。

## 26. MVP 驗收
1. 至少一個測試帳號完成正式 API 授權與發布
2. 一個核心主題可產生多平台差異化版本
3. 黃燈／紅燈正確進入人工審核
4. 重送不重複發文
5. 發布失敗可重試並保留錯誤
6. 每日清單可查看、停用、改時間、插入內容
7. 素材可追溯來源與使用紀錄
8. NAS 索引不修改原始檔
9. GitHub Actions 測試通過

## 27. 完整版驗收
1. 每週穩定 450～550 則，且不靠大量複製
2. 9 個可操作 Facebook 帳號依定位分流
3. IG、YouTube、Threads、TikTok 依優先級與成效分配資源
4. NAS 可自然語言搜尋照片與影片片段
5. 短影音可自動裁切、字幕、直式化、Logo、CTA、標籤、音樂與轉場
6. 一般內容自動，高風險攔截並人工審核
7. Dashboard 可一鍵暫停全部自動發布
8. Token、Retry、Log、Metrics、Audit Log 完整
9. AI 可依成效調整內容比例，但受多樣性與上限約束

## 28. 待確認
- 各平台 API 實際申請與審核狀態
- Facebook 9 個可操作帳號的實際帳號類型
- IG、YouTube、TikTok、Threads 帳號名稱與 OAuth 權限
- NAS 型號、記憶體、Container Station / Docker 能力與資料量
- 品牌字體、Logo 安全區、字幕模板、地區主色色碼
- 公司授權音樂庫
- 外部商用圖庫 API 最終選型
- 正式部署採 NAS、內部伺服器或 VPS
- Dashboard 使用者與角色權限

## 29. 最終原則
成功標準不是單純把 500 則內容發出去，而是建立一套可長期運作、可追蹤、可停用、可人工介入、能利用公司既有素材並持續從成效中學習的 AI 社群內容生產系統。

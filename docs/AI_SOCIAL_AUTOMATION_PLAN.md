# AI 社群內容自動化專案大綱

## 專案目標
建立 AI 社群編輯部，將旅遊內容自動完成選題、生成、查重、風險檢查、圖片匹配、排程、發布與成效回收。

## 目前社群出口
- Facebook：約 7 個
- YouTube：2 個
- Instagram：1 個
- TikTok：2 個
- Threads：1 個

## 500 則策略
採「核心主題 × 多版本 × 多平台」模式。
例如 50 個核心主題 × 平均 10 個變體 ≈ 500 則。

## 技術選型
- 自建：AI Content Engine / Quality Engine
- 發布引擎：Postiz 優先
- 備選：BrightBean Studio
- 儲存：PostgreSQL / Supabase 類型資料庫
- 自動化：Make.com 或自建 worker
- 發布：官方 API 優先

## 執行環境與部署策略
本專案不限定只能在個人電腦執行。開發、測試與正式上線應分成不同階段。

### 1. 個人 Windows 電腦
用途：第一階段 POC 與開發測試。

優點：
- 最容易開始測試。
- 適合檢查 Postiz、AI 內容流程、排程與 Mock Publisher。
- 不需要先購買額外主機。

限制：
- 電腦關機、睡眠或網路中斷時，自動化流程會停止。
- 不適合作為最終 24 小時正式服務主機。

### 2. 公司 NAS / 內部伺服器
用途：第二階段內部長時間測試，或作為正式部署候選。

條件：
- 主機需可長時間開機。
- 需支援 Docker / Container 類型服務。
- CPU、記憶體與儲存空間需足以同時執行 Postiz、PostgreSQL、Redis、Temporal 與本專案服務。
- 需評估 HTTPS、網路、防火牆、備份與外部 OAuth callback 設定。

優點：
- 公司可自行掌控資料與環境。
- 可降低長期雲端主機成本。

### 3. 雲端 VPS / 雲端伺服器
用途：正式 24 小時自動發布環境。

優點：
- 24 小時運作，不受個人電腦開關機影響。
- 較容易提供固定網域、HTTPS 與 OAuth callback。
- 適合執行定時排程、Token 更新、失敗重試、資料同步與自動發布。

正式環境建議至少具備：
- Docker / Docker Compose
- 固定網域
- HTTPS
- PostgreSQL 備份
- Log / Monitoring
- 自動重啟
- Token / Secret 安全管理

## 建議部署順序
1. Windows 本機完成 POC。
2. 確認 AI 產文、查重、風險檢查、排程與 Mock Publisher 正常。
3. 啟動 Postiz，先接 1 個測試社群帳號。
4. 完成真實發布測試與 Token 更新測試。
5. 評估公司 NAS 是否適合作為 24 小時正式主機。
6. 若 NAS 效能、外網或維護條件不適合，改部署至雲端 VPS。
7. 正式環境穩定後，再逐步接入 13 個社群出口。

## 正式環境必要能力
正式系統必須能在無人操作時持續執行：
- 定時產生內容
- 自動排程
- Token 到期檢查與更新
- 發布失敗重試
- 內容與圖片資料同步
- 發布紀錄保存
- 錯誤告警
- 成效數據回收

因此正式上線後，不應依賴某一台個人電腦保持開機。
